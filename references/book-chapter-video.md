# 书籍章节 → 系列短视频(在 teaching-script.md 七步流程之上追加)

适用:用户给出一份"书籍章节调研报告/目录"(`*章节内容调研.md`),要求把每章内容做成短视频(共 N 部)。

## 1. 信源纪律(最重要)
- 调研报告是**唯一信源**。报告通常分三层:结构事实(章名/节名/顺序)、主题证据(摘要/书评支持的判断)、未核验边界(节内细节/具体证明)。
- 只讲前两层支持的内容;**未核验边界绝不虚构补足**(不自行添加"书中某节必然讲了某定理的某证明"之外的细节)。
- 讲稿里附覆盖度清单时,逐条标注对应报告的哪一节/哪条证据。
- 报告若含"待实物核验"项,视频里对应内容用"据目录/据摘要"级别的措辞,不用断言句。

## 2. 系列化规范
- 工作目录:`workspace/<书名拼音>/chNN/`(ch01、ch02…),每章独立成片。
- 统一片头:`<书名简称> ①:章名`(圈号数字按章序);统一标题版式、总结条版式、配色。
- **章间钩子**:每部结尾"下一章"条预告下一章的核心悬念(从调研报告的章节递进关系里找,如"这套体系会被谁撬开第一条缝?")。
- 全部完成后可按章序 ffmpeg `-c copy` 无损拼合集(同参数渲染,可直接 concat)。

## 3. 问题链来源
- 不问"这章讲了什么",问"这一章的**主题张力**是什么"(如第1章:数与形对不上;第2章:完美规则里埋着雷)。
- 每章 4-7 个场景、28-40 拍;节名(1.1、1.2…)必须全部出现,但按问题链重排叙事顺序。

## 4. 数学内容口播纪律
- **符号不上口播**:√2→"根号二";a²+b²=c²→"a 平方加 b 平方等于 c 平方";≤→"不超过";→→"推出"。
- 符号可以上画面(白板字体 BD 支持 √ ² 等常用符号;HW 手写体缺字,公式一律用 BD)。
- 数值必须可核:引用具体数字(如 Plimpton 322 最大斜边 18541)前先核对来源。

## 5. TTS 网络抖动经验(edge-tts 常见)
- 链式脚本必须带**清理+循环重试**:每次重试前删除 ffprobe 失败或时长<0.2s 的坏分片,循环直到 build 成功(服务恢复后增量补齐,已成功分片自动跳过)。
- 实测可用参数:失败后 sleep 15-25s 再试,一般 10 分钟内能熬过一轮服务抖动。
- **绝不能并行跑两个 build 实例**(会互相删写 parts 目录导致竞态损坏);启动新链前先 `tasklist` 查残留 python 进程。

## 6. 产物清单(每章)
`讲稿.md`、`make_boards_and_plan.py`、`boards/*.png`、`plan.build.json`、`plan.json`、`audio/narration/*.mp3`、`out/chNN.mp4`。
质检:`check_assignment.py` 必须两清(build 前对 plan.build.json、build 后对 plan.json)。
